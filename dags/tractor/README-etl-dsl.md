# ETL DSL Documentation

## Overview

This document describes the Domain-Specific Language (DSL) used for defining Extract, Transform, Load (ETL) processes. The DSL allows users to specify data sources, extraction commands, transformation steps, and loading procedures in a structured and readable format.

By using YAML format, it ensures readability and ease of use, allowing users to quickly set up and manage their ETL workflows. It is important to note that this DSL is not a general graph definition language, but a specific set of shorthand configurations tailored for defining ETL processes. This specialization allows for more concise and focused definitions, making it easier to manage ETL tasks and their dependencies.

## Structure ETL DSL Schema

This repository contains a JSON schema for defining a Domain-Specific Language (DSL) for ETL (Extract, Transform, Load) projects. The schema provides a structured way to define ETL processes, including commands, defaults, sources, and storage objects.

### Schema Overview

The schema is defined using JSON Schema Draft-07 and includes the following main components:

- **Command**: Represents a command to be executed, which can be a string or an object with `operator_type` and `command` properties.
- **Defaults**: Defines default values for the ETL project, including bucket information, operator type, and default commands.
- **StorageObject**: Represents an input or output storage object, which can be a string or an object with properties like `url`, `path`, `type`, `name`, and `description`.
- **Source**: Represents a data source with properties for commands, inputs, and outputs.

### Schema Definitions

#### Command

A command can be either a string or an object with the following properties:

- `operator_type`: The type of operator to be used (e.g., `PythonOperator`, `BashOperator`, `TESOperator`).
- `command`: The command to be executed.

#### Defaults

Defines default values for the ETL project:

- `bucket`: The name of the bucket where data will be stored.
- `bucket_prefix`: A prefix to be used for all data stored in the bucket.
- `bucket_scheme`: The scheme used for accessing the bucket (e.g., `s3`, `gs`, `abfs`).
- `operator_type`: The default operator type to be used for executing commands.
- `extract_commands`: Default extraction commands to be used if not specified in the sources section.
- `transform_commands`: Default transformation commands to be used if not specified in the sources section.
- `load_commands`: Default load commands to be used if not specified in the sources section.

#### StorageObject

Represents an input or output storage object, which can be either a string or an object with the following properties:

- `url`: The URL of the storage object.
- `path`: The path of the storage object.
- `type`: The type of the storage object (`FILE` or `DIRECTORY`).
- `name`: The name of the storage object.
- `description`: The description of the storage object.

#### Source

Represents a data source with the following properties:

- `id`: A unique identifier for the data source.
- `extract_commands`: A list of commands to extract data from the source.
- `transform_commands`: A list of commands to transform the extracted data.
- `load_commands`: A list of commands to load the transformed data.
- `inputs`: A list of input files required by the extraction and transform commands.
- `outputs`: A list of output files generated by the extraction and transform commands.

## Example

Here is an example of an ETL `Process` defined using the DSL:

```yaml
---
# This globally unique id is used to identify the ETL Project in the console and logs
id: example_etl

# these defaults are used to expand and fill in missing values in the sources section
defaults:
  # e.g. all data will be stored in the bucket named 'ExampleBucket'
  bucket: ExampleBucket
  bucket_prefix: example
  bucket_scheme: s3
  # e.g. all commands will be executed using the BashOperator
  operator_type: airflow-operator://BashOperator
  extract_commands:
    - echo "extract"
  transform_commands:
    - echo "transform"

sources:
  - id: source1
    # this source overrides the default extract commands
    extract_commands:
      - python3 source1/src/download-data.py
      - python3 source1/src/download-lookup.py
    # this source uses the defaults.transform_commands
    outputs:
      # specific files are identified as outputs
      # on successful completion of the extract and transform commands, these files will be uploaded to the bucket
      - source1/raw/data.json
      - source1/raw/lookup.tsv
      - source1/processed/combined.ndjson

  - id: source2
    # this source overrides the default extract and transform commands
    extract_commands:
      - wget https://example.com/data.csv -O source2/raw/data.csv
    transform_commands:
      - python3 source2/src/process.py
    outputs:
      # directories are used as outputs
      - source2/raw
      - source2/processed

  - id: source3
    # this source uses the default extract and transform commands
    load_commands:
      # this source has a separate load command that will be scheduled after its transform
      - echo "load-source3-sidecar"
    inputs:
      # directories are used as inputs
      # the contents of these directories will be downloaded from the bucket and made available to the extract and transform commands
      - source3/external-data

load_commands:
  # these commands will execute after all sources have been processed
  - echo "load-all"


```

## Sections

### `id`

The `id` field provides a unique identifier for the ETL process. This helps in distinguishing between different ETL processes.

### `defaults`

The `defaults` section specifies default settings for the ETL process, including:

- `bucket`: The name of the bucket where data will be stored.
- `bucket_prefix`: A prefix to be used for all data stored in the bucket.
- `bucket_scheme`: The scheme used for accessing the bucket (e.g., `s3`).
- `operator_type`: The default operator type to be used for executing commands.
- `extract_commands`: Default extraction commands to be used if not specified in the `sources` section.
- `transform_commands`: Default transformation commands to be used if not specified in the `sources` section.

### `sources`

The `sources` section contains a list of data sources. Each source has the following fields:

- `id`: A unique identifier for the data source.
- `extract_commands`: A list of commands to extract data from the source.
- `transform_commands`: A list of commands to transform extracted.
- `load_commands`: A list of commands load transformed data.
- `inputs`: A list of input files required by the extraction and transform commands.
- `outputs`: A list of output files generated by the extraction and transform commands.

### `load_commands`

The `load_commands` section contains a list of commands to load the processed data into the target system. These commands are executed after the extraction and transformation steps.

## Usage

To define an ETL process using this DSL, create a YAML file with the structure described above. The ETL process can then be executed by a compatible ETL engine that interprets the DSL and performs the specified extraction, transformation, and loading steps.

## Task Interface
### Inputs and Outputs

The DSL will expand inputs and outputs provided by the user into the following structure using the contents of the `Defaults` section.

* description: A description of the output.
* url: The URL or path where the output data will be stored.
* path: The local path where the output data will be stored.
* type: The type of the output (e.g., FILE, DIRECTORY).

Each `Source` in `Process`' inputs and outputs are associated with a `Dataset`
Airflow Datasets can be scheduled based on the dependencies defined in the ETL process. The scheduling ensures that tasks are executed in the correct order, respecting the dependencies between different datasets. 

## Resulting DAGs

The ETL process defined using this DSL will be translated into a Directed Acyclic Graph (DAG) by the ETL engine. The DAG will represent the workflow of the ETL process, with nodes corresponding to tasks and edges representing dependencies between tasks. The DAG can be visualized and executed by the ETL engine to perform the specified ETL operations.

Source DAG Creation:  Each Source in the ETL process creates a Directed Acyclic Graph (DAG) with the following characteristics:
* Extract: The extract step is triggered by either a Console operation, CLI command, API call, or scheduled similar to cron.
* Transform: The transform step is triggered when the extract step updates its Dataset.
* Load: The load step is triggered when the transform step updates its Dataset.

Process DAG Creation: The Process DAG is created by combining the DAGs of all the Sources in the ETL process. The Process DAG has the following characteristics:
* Load: The load step is triggered when all the Sources have completed their Load steps.

## Conclusion

This DSL provides a simple and structured way to define ETL processes. By using YAML format, it ensures readability and ease of use, allowing users to quickly set up and manage their ETL workflows.
